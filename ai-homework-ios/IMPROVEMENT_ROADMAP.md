# План улучшений AI Homework

Основа плана: [PROJECT_AUDIT.md](PROJECT_AUDIT.md) от 2026-11-16. Номера AUD-xx взяты из его раздела G. План эволюционный: файлы не удаляются, приложение не переписывается, платных API и обязательной авторизации нет, всё совместимо с установкой через SideStore.

## Целевая архитектура

Слои остаются прежними. Меняются только «швы» между ними: появляются протоколы, через которые компоненты подменяются в тестах. Это и есть внедрение зависимостей (DI).

```
App (iOS)      AIHomeworkApp создаёт ModelContainer, AppSettings, HistoryStore,
               SolveCoordinator и передаёт их в AppModel(dependencies:)
                    │
Features (iOS) SolveViewModel(input, coordinator: SolveCoordinating,
               history: HistoryStoring, recognizer: TextRecognizing, feedback: FeedbackPlaying)
               без ModelContext, withAnimation и Haptics внутри; запись — по UUID
                    │
Services (iOS) SolveCoordinator — тонкий адаптер: JPEG, снимок настроек, ProviderFactory
               HistoryStore (SwiftData, VersionedSchema), OCRService (отменяемый),
               ImageIngest (ImageIO: уменьшение при загрузке, обрезка по оригиналу)
                    │
Engine (SwiftPM, Linux, swift test)
               SolvePolicy: диспетчер → точный решатель → API → Apple Intelligence → отказ
               InputGuard: лимит длины/глубины, снятие нумерации
               LocalSolverPipeline + «граница уверенности» (решатель доказывает, что задача его)
               Решатели, TaskRouting, ModelPrompting, LanguageModelProvider, SubjectCatalog
```

Что меняется и почему:
1. **Конвейер решения уходит в Engine как `SolvePolicy`** (AUD-31). Политика принимает `SolveRequest` (текст, предмет, `imageJPEG: Data?`, источник условия, уверенность OCR), снимок настроек и массив `[any LanguageModelProvider]`. Возвращает `SolveOutcome` с видом сбоя: `network / timeout / auth / notConfigured` (AUD-22). Теперь эти ветки тестируются на Linux с поддельными провайдерами.
2. **Диспетчер.** Сбой отключает API только при сетевой ошибке или 401/403. При HTTP 400 запрос повторяется без картинки. Картинка уходит только по выбранной владельцем политике (AUD-20, решение 1).
3. **Точный решатель.**
   - Перед разбором стоит `InputGuard` (AUD-14).
   - Решатель выбранного предмета окончателен; чужие решатели принимаются только при сильных признаках своего предмета (AUD-07).
   - Решатель обязан доказать, что использовал все данные (AUD-10, AUD-11).
4. **Нейросеть по API.** Порядок ответа «шаги → ответ», текст обёрнут в `<task>`, есть лимит токенов (AUD-34, AUD-35).
5. **Apple Intelligence.**
   - Если язык не поддерживается, провайдер считается недоступным.
   - Дальше — роль офлайн-«нормализатора» условия (guided generation), считает по-прежнему точный решатель (AUD-30).
6. **Метка достоверности = вычисление + источник условия.** Новые подписи: «условие набрано», «распознано с уверенностью N %», «переписано нейросетью». Метку «Точное решение» без оговорок получает только набранное или уверенно распознанное условие (AUD-18).
7. **Хранение.**
   - `HistoryStore` с `SchemaV1` и `SchemaMigrationPlan`; ошибки сохранения видны пользователю; одна функция удаления (AUD-25, AUD-26).
   - Фото: ImageIO-уменьшение при загрузке, обрезка по оригиналу, одно JPEG-кодирование для API и истории (AUD-28, AUD-66).
   - Класс защиты и бэкап — по решению владельца (AUD-39).
8. **Навигация.**
   - `AppRoute` остаётся.
   - Добавляется `SolveInput.restored(text:image:subject:autoSolve:)` (AUD-24).
   - Оверлей решения становится модальным для доступности и получает свой `NavigationStack` (AUD-52).
   - Последовательность показов управляется по `onDismiss`, а не таймером в 450 мс (AUD-42).

## Порядок реализации

Оценки даны для одного разработчика. Всего примерно 35–50 рабочих дней. Каждую фазу можно выпускать отдельной сборкой через SideStore.

### Фаза 0. «Правдивость и безопасность»
- **Цель.** Приложение не обещает того, чего не делает, не падает на длинном вводе и не теряет историю. Дальнейшие исправления защищены CI.
- **Задачи:**
  - AUD-15: исправить тексты о приватности в запросе камеры, PDF, настройках, главном экране, README и `source.json`;
  - AUD-14: `InputGuard`;
  - AUD-16: новая область — новая запись в истории;
  - AUD-32 (часть): `needs: engine-tests`, закреплённый Xcode, проверка расширения, dSYM;
  - AUD-18 (часть): временно понизить метку до «Проверьте Дано» для численной ветки и для условия, переписанного диспетчером;
  - AUD-36: буфер обмена → стадия проверки;
  - AUD-37: предупреждение для полного скриншота, отказ при слишком малом выделении;
  - AUD-38: ключ привязан к хосту;
  - AUD-93: ephemeral-сессия без редиректов на чужой хост;
  - AUD-96: маскирование ошибок сервера;
  - после ответа владельца на вопрос 1 — выбранная политика отправки фото.
- **Критерий готовности (проверяемый):**
  - поиск по проекту фраз «на этом устройстве», «без отправки», «без сети» находит только утверждения, верные для текущего кода;
  - юнит-тест с 10 000 слагаемыми `1+…+1` и 2000 вложенных скобок под `ulimit -s 512` возвращает честный отказ, а не SIGSEGV;
  - в workflow у job `ipa` есть `needs: engine-tests`;
  - тест VM или ручная проверка: две разные области одного фото дают две записи в истории.
- **Объём:** 2–3 дня (10 задач S + политика фото M).
- **Зависимости:** ответ владельца на вопрос 1 нужен только для последней задачи. Остальное можно делать сразу.
- **Что проверить на iPhone:**
  - в Настройки → Конфиденциальность → Камера и в первом запросе камеры текст правдив;
  - в PDF решения от API нет фразы «без отправки данных»;
  - вставка длинного текста (скопировать 3000 раз «1+») не роняет приложение;
  - «Выбрать другую область» не стирает предыдущую запись.

### Фаза 1. «Корректность движка»
- **Цель.** Метка «Точное решение» больше не стоит на неверных ответах из аудита.
- **Задачи:**
  - уравнения: AUD-01, AUD-02, AUD-03, AUD-04;
  - химия: AUD-05, AUD-06;
  - конвейер и разбор текста: AUD-07, AUD-08, AUD-09, AUD-10, AUD-11, AUD-12, AUD-13, AUD-17, AUD-33;
  - мелкие поправки: AUD-60, AUD-61, AUD-62, AUD-63, AUD-99.
  - Порядок: сначала регрессионные тесты (они должны падать), затем исправления.
- **Критерий готовности (проверяемый):**
  - все 31 неверный ответ из QA (`audit/software-tester.md`) и 20 неверных ответов из прогона судьи превращены в регрессионные тесты, и все они проходят;
  - 57 старых тестов проходят;
  - ни один ответ движка не длиннее 2000 символов;
  - `|x| = x` и `sin²x + cos²x = 1` решаются быстрее 0,3 с (Linux, debug);
  - чистая сборка движка без предупреждений.
- **Объём:** 6–9 дней (6 задач M + 14 S).
- **Зависимости:** Фаза 0 (CI должен ловить регрессии).
- **Что проверить на iPhone:** решить с фото или ввести текстом:
  - «3. Найдите НОД чисел 12 и 18» → 6;
  - `x/x = 1` → «x ≠ 0»;
  - `Молярная масса H2S04` → предупреждение о 0/O;
  - «Найдите нули функции f(x) = x² − 4x + 3» → 1; 3;
  - «Переведите −5 в двоичную» → −101₂ или честный отказ;
  - на фото тетради с `2x² − 5x + 2 = 0` → 1/2; 2 или пометка «Проверьте».

### Фаза 2. «Стабильность и память»
- **Цель.** Решение не обрывается при сворачивании, не «висит» дольше лимита, не съедает память на больших фото и сканах. История не пропадает молча.
- **Задачи:**
  - сначала AUD-31 (`SolvePolicy` в Engine и протоколы), без неё следующие задачи не закрепить тестами;
  - сеть и лимиты: AUD-20, AUD-21, AUD-23, AUD-30;
  - хранение: AUD-25, AUD-26, AUD-39 (по решению 2), AUD-45 (экспорт и импорт истории в файл);
  - изображения: AUD-27, AUD-28;
  - прочее: AUD-41, AUD-42, AUD-46, AUD-47, AUD-64, AUD-92.
- **Критерий готовности (проверяемый):**
  - тесты `SolvePolicy` с поддельными провайдерами на Linux:
    - сбой диспетчера с HTTP 400 не отключает решение по API;
    - сетевая ошибка даёт `failure(.network)`;
    - неподдерживаемый язык → Apple Intelligence не вызывается;
  - тест `Deadline.run` с операцией, игнорирующей отмену, возвращается не позже лимита + 0,2 с;
  - в коде есть `VersionedSchema`, `beginBackgroundTask`, `AVCaptureDevice.authorizationStatus`;
  - `try? context.save()` нигде не используется.
- **Объём:** 8–12 дней (около 10 задач M + 6 S).
- **Зависимости:** Фаза 0. Для AUD-39 нужен ответ на вопрос 2, для AUD-27 — на вопрос 4.
- **Что проверить на iPhone:**
  - отправить задание в API, сразу свернуть приложение на 10–20 с и вернуться: ответ приходит, «соединение потеряно» не появляется;
  - отсканировать 4 страницы: интерфейс не замирает, текст распознаётся;
  - открыть фото 48 Мп: приложение не вылетает;
  - экспортировать историю в файл и импортировать обратно;
  - в «Настройках → Поделиться диагностикой» есть отчёт MetricKit (через сутки использования).

### Фаза 3. «UX основного сценария»
- **Цель.** Сценарий «фото → обвести → проверить → ответ» понятен, управляем и честен.
- **Задачи:**

  - стадия «Решаю» и ошибки: AUD-22 («Остановить», карточка «Нет связи», «Повторить»);

  - выделение и ввод: AUD-40, AUD-53, AUD-54;
  - нейросеть и OCR: AUD-34, AUD-35, AUD-48, AUD-56;
  - прочее: AUD-43, AUD-81, AUD-90.
- **Критерий готовности (проверяемый):**
  - XCUITest на симуляторе (или ручной сценарий) с поддельным провайдером:
    - «Остановить» возвращает на стадию проверки с тем же текстом;

- **Объём:** 6–8 дней.

- **Критерий готовности (проверяемый):**

- **Критерий готовности (проверяемый):**
  - CI зелёный только при прохождении unit-тестов движка, unit-тестов приложения и минимум 6 XCUITest-сценариев из раздела ниже;

- **Объём:** 3–5 дней.
- **Зависимости:** протоколы из Фазы 2. Unit-тесты движка пишутся с Фазы 1, в этой фазе добавляется только инфраструктура приложения и UI.

## Риски плана

- **Нет Mac.** Ошибки UI и платформы видны только на iPhone или в XCUITest на CI. Поэтому Фаза 2 начинается с AUD-31 и MetricKit (AUD-64): без них диагностика сбоев идёт вслепую.
- **Правки разбора OCR-записей (AUD-12, AUD-17) могут сломать сегодняшние верные ответы.** Поэтому в Фазе 1 тесты пишутся до исправлений, и все 57 существующих тестов обязаны проходить.
- **Временное понижение метки (Фаза 0) сделает приложение на вид «менее уверенным».** Это честно, но владельцу стоит быть к этому готовым.
- **Миграция SwiftData.** Вводить `SchemaV1` нужно без изменения модели, первым отдельным релизом, и проверять обновлением поверх старой сборки в SideStore.
- **Зависимость от решений владельца** (фото, бэкап, автозапуск, сканер) может задержать отдельные задачи. Остальные задачи фаз от этих решений не зависят.
- **Версия Xcode в CI.** Закрепление версии и переход на iOS 26 SDK меняют внешний вид (Liquid Glass) и предупреждения. Нужна контрольная сборка.
- **Оценки сроков** (35–50 дней) сделаны по чтению кода. Задачи с пометкой «устройство» могут оказаться и проще (проблемы нет), и сложнее.
- **Ограничения SideStore:** 7-дневная подпись, бесплатный Apple ID, смена Apple ID стирает данные. До выпуска экспорта истории (AUD-45) любая переустановка — риск потери данных.
