# Аудит проекта AI Homework (iOS)

**Дата:** 2026-11-16
**Комиссия:** Senior iOS Engineer ([отчёт](audit/ios-engineer.md), находки IOS-n), SwiftUI Architect ([отчёт](audit/swiftui-architect.md), ARCH-n), AI/ML Engineer ([отчёт](audit/ai-ml-engineer.md), AI-n), UI/UX Designer ([отчёт](audit/ui-ux-designer.md), UX-n), Software Tester ([отчёт](audit/software-tester.md), QA-n), Performance Engineer ([отчёт](audit/performance-engineer.md), PERF-n), Security & Privacy Engineer ([отчёт](audit/security-engineer.md), SEC-n). Сводку составил главный судья (Principal Engineer), который в экспертной проверке не участвовал. Материалы дела: [audit/case.md](audit/case.md).

**Методика.**
- Эксперты работали изолированно, отчёты друг друга не видели. Если одну проблему независимо нашли несколько экспертов, это считается признаком достоверности. В реестре такие находки объединены, в колонке «Источники» перечислены все ID.
- **Что реально запускалось.**
  - QA прогнал 57 существующих тестов движка в Docker `swift:6.2` на Linux: 57 из 57 прошли. Затем QA прогнал 184 проверочных задания: 31 ответ неверный, из них 27 с меткой «Точное решение». Ещё QA воспроизвёл краш SIGSEGV.
  - PERF сделал микробенчмарк движка (release-сборка, Linux).
  - Судья перепроверил спорные утверждения собственным прогоном: 33 входа на **копии** движка во временной папке, код проекта не менялся. Результат:
    - все 11 повторённых находок QA воспроизвелись;
    - из 22 входов AI-эксперта (он сам ничего не запускал) 20 дали неверный ответ, 18 из них с меткой «Точное решение»;
    - подтвердилось замечание PERF: на `x² + 1000000001x + 1 = 0` движок отвечает «Действительных корней нет».
- **Что не запускалось.** Приложение не запускалось ни на iPhone, ни на симуляторе. Распознавание Vision, Apple Intelligence, камера, память и плавность интерфейса не проверялись. SwiftUI/UIKit-код в этой среде не компилируется. Проект собирается в GitHub Actions, но предупреждения компилятора не разбирались.
- **Статусы проверки в реестре:**
  - «тест»: подтверждено прогоном QA или судьи (только движок, Linux);
  - «замер Linux»: цифры PERF с сервера, не с iPhone;
  - «код»: подтверждено чтением кода (судья открывал файл);
  - «устройство»: без iPhone подтвердить нельзя.

Обозначения: **P0** — неверный ответ с меткой «Точное решение», краш, потеря данных или ложное обещание приватности; **P1** — важно для основной функции или стабильности; **P2** — средняя важность; **P3** — косметика. Сложность: **S** до 2 ч, **M** до 1 дня, **L** несколько дней.

## A. Общая оценка

**Итог: 5/10.**

Каркас приложения сделан хорошо:
- движок отделён от интерфейса и тестируется без Mac;
- навигация типизирована;
- ключ API лежит в Связке ключей (Keychain, защищённое хранилище iOS для секретов);
- нет аналитики и сторонних SDK;
- тяжёлая работа в основном вынесена с главного потока (главный поток — тот, что рисует интерфейс; если его занять, интерфейс «замирает»).

Главную функцию подводят две вещи.
1. **Метке «Точное решение» нельзя доверять.**
   - В проверочном наборе QA неверен примерно каждый шестой ответ (31 из 184). 27 неверных ответов показаны как «Вычислено точным алгоритмом на устройстве и проверено».
   - Прогон судьи дал ещё 18 таких ответов на типичных школьных записях: номер задания, интеграл, «нули функции», проценты по цепочке.
   - Длинный ввод роняет приложение.
2. **Тексты о приватности не соответствуют поведению.** В каждом PDF и в системном запросе доступа к камере написано, что данные не покидают устройство. На самом деле при настроенном API фрагмент фото уходит на сервер ещё до точного решателя.

Обе проблемы исправляются без переписывания приложения. Большинство исправлений небольшие (S/M).

## B. Архитектура

**Сильные стороны (проверено чтением кода):**
- Граница движка закреплена сборкой. `Package.swift` собирает `AIHomework/Engine` как отдельный таргет на чистом Foundation. Если в движок попадёт `import UIKit`, тесты на Linux упадут (ARCH, сильная сторона 1).
- Навигация типизирована: `AppRoute` передаёт `UUID`. Экран записи сам находит её через `@Query` и честно показывает «Задание удалено» (`ProblemDetailView.swift:18-29`).
- Машина этапов `SolveViewModel` (выбор → распознавание → проверка → решение → результат) держит одну рабочую задачу. После каждого `await` проверяется отмена.
- Решение хранится в истории JSON-блобом, фото вынесено в `externalStorage`, поэтому схема базы почти не меняется.
- Быстрые действия передаются без App Group и entitlements через «почтовый ящик» в `UserDefaults`. Это удобно для сайдлоада с бесплатным Apple ID (IOS, сильная сторона 3).
- Контракт `LanguageModelProvider` импортирует только Foundation, поэтому его можно перенести в движок.

**Слабые стороны:**
- **Главная логика не тестируема (AUD-31).** `SolveCoordinator.solve` (`Services/SolveCoordinator.swift:84-211`) содержит сразу всё: политику пяти шагов (диспетчер → точный решатель → API → Apple Intelligence → отказ), создание провайдеров, чтение настроек и UIKit. Именно этот код стоит за жалобами владельца «бесконечно решает» и «соединение потеряно», и ни одна его ветка не покрыта тестами.
- **Нет слоя хранения (AUD-25, AUD-26).** `ModelContext` используется прямо во View и VM. Ошибки сохранения проглатываются. «Удалить всю историю» реализовано двумя разными способами.
- **ViewModel держит живой объект SwiftData** (`record`), а не его идентификатор (ARCH-6). SwiftData — системная база данных Apple, в ней хранится история.
- **Точка расширения `providers()` в `solve()` не используется** (ARCH-4).
- **Сценарий решения показан оверлеем** (слоем поверх экрана через ZStack). Модальность сделана только запретом касаний, поэтому VoiceOver видит экран под ним (ARCH-7).
- **Наследие «стеклянного» дизайна:** часть параметров игнорируется, есть мёртвый код (ARCH-9, UX-22). Удалять его можно только с разрешения владельца.

Целевая эволюционная архитектура описана в [IMPROVEMENT_ROADMAP.md](IMPROVEMENT_ROADMAP.md).

## C. Интерфейс

**Что хорошо (код):**
- Токены цвета применяются дисциплинированно.
- Поверхности сделаны по правилам Linear: без теней и размытия.
- Пружины спокойные.
- Пустые состояния сделаны через `ContentUnavailableView`.
- Этапы решения прозрачны: видно, работает диспетчер, точный решатель или модель.
- Метка достоверности подписана текстом, а не только цветом (UX, сильные стороны).

**Что мешает основному сценарию «фото → обвести → ответ»:**
1. После OCR решение запускается сразу (`SolveViewModel.swift:161-162`). Экран проверки текста с процентом уверенности почти никто не увидит. Жалоба «x читается как ×» превращается в неверный ответ раньше, чем пользователь видит текст (AUD-19).
2. Стадия «Решаю» длится до ~2,5–3 мин в худшем случае. Кнопки «Остановить» с возвратом к условию нет. Ошибку сети пользователь видит как «Нужна нейросеть» с кнопкой «Настроить нейросеть» (AUD-22).
3. «Изменить и решить» из истории ничего не даёт изменить. Задание, решённое только по картинке, повторно отправляется как строка «Задание на изображении» (AUD-24).
4. При выделении области нельзя увеличить изображение (AUD-53). На iPhone SE с клавиатурой поле ввода уходит за экран (AUD-54).

**Доступность:**
- Заголовки и кнопки не масштабируются при крупном системном тексте (Dynamic Type), потому что используется `Font.system(size:)` (AUD-49).
- Третичный текст имеет контраст 2,6:1 в светлой теме при норме 4,5:1 (AUD-50).
- Смена стадий не озвучивается VoiceOver (AUD-52).
- «Уменьшение движения» учитывается частично (AUD-51).

Всё это проверено чтением кода. Внешний вид требует визуальной проверки на iPhone.

## D. AI и распознавание

**Как работает сейчас (по коду):**
- **OCR.** Используется Apple Vision `VNRecognizeTextRequest` (`.accurate`, ru+en). Если в тексте много цифр и знаков, делается второй проход без языковой коррекции, и он **полностью заменяет** первый (`OCRService.swift:48-57`).
- **Подготовка картинки.** Изображение сначала уменьшается до 2600 px и только потом обрезается по выделению. Мелкая формула теряет пиксели (AI-14).
- **Структура формул не распознаётся.** Степени, дроби и корни передаются эвристиками: `x2 → x²` только после буквы, `×` между операндами считается умножением.
- **С API пользователя** запросов два, и в оба уходит JPEG фрагмента:
  1. «диспетчер» (до 25 с) переписывает условие для точного решателя или берёт задачу себе;
  2. полное решение (до 75 с, без лимита токенов).
- **Без API:** точный решатель → Apple Intelligence (iOS 26) → честный отказ.
- **Core ML-моделей в проекте нет**, их удалили по решению владельца.

**Ограничения:**
- Метка `exact` («Точное решение») ставится только по типу решателя. Её получает и условие, переписанное нейросетью, и условие, распознанное с низкой уверенностью (AUD-18).
- Если запрос диспетчера завершился любой ошибкой (модель без зрения, пустой ответ «рассуждающей» модели, тайм-аут), API отключается на всё решение (AUD-20).
- Apple Intelligence сообщает «доступна», даже если язык не поддерживается (`AppleIntelligenceProvider.swift:35`). Русского среди поддерживаемых языков, по данным AI-эксперта, нет (нужно проверить на устройстве) (AUD-30).

**Три категории функций.** Категория 1 — обычные алгоритмы, это не ИИ. «Статус сейчас» — по коду и тестам движка.

| Объяснение шагов | 1 для точных решателей (шаблоны), 3 для остального | Работает | Шаблонные шаги — сильная сторона |

## E. Производительность

- **Движок (замер Linux):**
  - 0,2–3 мс на примеры каталога;
  - 11–51 мс на трансцендентные уравнения и тексты по 3,5 тыс. символов;
  - патологические входы занимают 1,9–2,5 с: `|x| = x`, `sin²x + cos²x = 1` (AUD-02).
  Для iPhone это относительная оценка.
- **Изображения, главный риск (код, на устройстве не измерено).**
  - Фото из галереи декодируется целиком на главном потоке, параллельно идёт ещё одно полное декодирование в фоне (AUD-28).
  - Сканер склеивает до 4 страниц в полном разрешении на главном потоке: по оценке ~130–140 МБ битмапа (AUD-27).
  - На снимках 48 Мп возможна выгрузка приложения системой из-за нехватки памяти (jetsam).
- **Сеть.** Фрагмент уходит дважды (диспетчер и решение), потоковой выдачи нет. Худшее время до ответа или отказа ≈ 25 + 6 + 75 + 60 с (AUD-48, AUD-22).
- **История.** `@Query` без лимита на главном экране. JSON решения и фото декодируются при каждом пересчёте экрана записи (AUD-46).
- **Анимации и прочее:** бесконечные анимации орба, размытие стека навигации, хаптика без `prepare()` (P3).
- **Инструментирования нет:** ни `os_signpost`, ни MetricKit. Без Mac разложить жалобу «долго решает» на этапы нечем (AUD-64).

## F. Безопасность и приватность

**Хранение данных:**
- Ключ API лежит в Keychain с `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`. Без синхронизации с iCloud, не в `UserDefaults`. Это правильно (код).
- История (текст, решение, фото ≤1600 px) хранится в SwiftData с классом защиты по умолчанию. Она **попадает в резервную копию iCloud**. Если выключить «Сохранять фото», уже сохранённые фото остаются (AUD-39, код; класс защиты — устройство).
- Временные скриншот и PDF не чистятся (AUD-92).

**Обработка изображений:**
- Метаданные EXIF и GPS удаляются перекодированием (код).
- При настроенном API в **каждом** задании с фото JPEG ≤1600 px уходит на адрес пользователя **до** точного решателя, двумя запросами (`SolveCoordinator.swift:99-118, 172-180`).
- Если ничего не выделено, уходит весь скриншот: статус-бар, уведомления, переписка (AUD-37).
- Текст из буфера обмена по быстрому действию уходит в API без показа (AUD-36).
- Противоречие с правилом владельца «не отправлять фото на внешние серверы» вынесено в «Решения, которые нужны от владельца».

**Ложные обещания (P0, AUD-15):**
- «Фотографии обрабатываются на этом устройстве» в запросе доступа к камере;
- «Решение получено на устройстве, без отправки данных на серверы» в **каждом** PDF;

## G. Критические проблемы

Сводка после объединения дубликатов: **99 проблем**, из них P0 — 16, P1 — 17, P2 — 31, P3 — 35. В экспертных отчётах было 148 находок; ещё две (AI-21, SEC-1) — вопросы к владельцу, они вынесены в отдельный раздел.

### P0

#### AUD-01. Дробно-рациональное тождество выдаётся как «Действительных корней нет»
- Источники: QA-1, AI-5 (2 эксперта)
- Код: `AIHomework/Engine/Math/EquationSolver.swift:525-526`, `solveRationalEquation`: `if degree == 0 { candidates = [] }`
- Причина: если числитель после переноса тождественно равен нулю, подходит любое x из ОДЗ (области допустимых значений). Код не отличает этот случай от ненулевой константы, когда решений нет. Для многочленов этот случай обработан, для дробей нет.
- Последствия: `x/x = 1`, `(x−1)/(x−1) = 1`, `(x²−9)/(x−3) = x+3` получают «корней нет» с меткой «Точное решение». Это классические задачи-ловушки на ОДЗ.
- Решение: если числитель нулевой, отвечать «x — любое число, кроме {корни знаменателя}». Добавить регрессионные тесты.
- Сложность: S. Статус: тест (QA: 5 из 5 проб; судья: `x/x = 1`, `(x²−9)/(x−3) = x+3`).

#### AUD-02. Уравнение с бесконечным множеством решений превращается в список из тысяч «корней»
- Источники: QA-2, AI-18
- Код: `EquationSolver.swift:840-850` (`NumericRootFinder.roots(of:grid:)`, ветка `if fa == 0`), сетка `:812-830`
- Причина: каждая точка сетки, где f = 0, добавляется как корень. Тождество на промежутке не распознаётся.
- Последствия:
  - `|x| = x` и `sqrt(x²) = x` дают «x₁ = 0; x₂ = 0,01; …»: 110–200 тыс. символов с меткой «точно», 1,9 с;
  - `sin²x + cos²x = 1` даёт 2,5 с (судья), тот же длинный список, метка «приближённо»;
  - такой текст попадёт в `Text`, SwiftData и PDF. Возможно подвисание интерфейса (устройство).
- Решение: если в сетке ≥3 нуля подряд, проверить тождество в случайных точках и ответить «любое x из промежутка …» с меткой не выше `approximate`. Ограничить число корней (например, 20) и длину ответа.
- Сложность: M. Статус: тест.

#### AUD-03. Численный поиск только на [−1000; 1000], но ответ помечен «точно»
- Источники: QA-3
- Код: `EquationSolver.swift:660-690` (`finish(... approximate: roots.contains { !$0.isExact })`), `:812-830`
- Причина: метка зависит от точности найденных корней, а не от полноты их множества. Оговорка о промежутке спрятана в примечаниях.
- Последствия: `|x − 1500| = 1000` → «x = 500» с меткой «точно», корень 2500 потерян (судья воспроизвёл). `sqrt(x) = 40` и `|x| = 2000` → «корней не найдено».
- Решение: численную ветку помечать не выше `approximate`, оговорку писать в сам ответ. Модуль раскрывать аналитически, корень убирать возведением в квадрат с проверкой, и только потом переходить к численному методу.
- Сложность: M. Статус: тест.

#### AUD-04. Проверка подстановкой в `Double` отбрасывает верные корни при больших коэффициентах
- Источники: QA-4; замечание PERF «вне области» (2 эксперта независимо)
- Код: `EquationSolver.swift:747-748`, `guard abs(left.double - right.double) <= 1e-6 * scale`
- Причина: малый корень вычисляется как разность близких чисел. Погрешность округления превышает допуск 10⁻⁶, и верный корень отбрасывается.
- Последствия:
  - `x² − 1000000x + 1 = 0` → один корень вместо двух;
  - `x² + 1000000001x + 1 = 0` → «Действительных корней нет» с меткой «точно», отброшены **оба** корня (судья).
- Решение: второй корень считать по Виету (`x₂ = c/(a·x₁)`). Корни вида p ± q√r проверять символьно. Допуск брать от масштаба коэффициентов.
- Сложность: S. Статус: тест.

#### AUD-05. Цифра 0 вместо буквы O (частая ошибка OCR) даёт неверную молярную массу
- Источники: QA-5
- Код: `AIHomework/Engine/Chemistry/ChemistrySolver.swift:86-93`, `readNumber`
- Причина: индекс с ведущим нулём («04», «02») принимается как число.
- Последствия: `H2S04` → 130 г/моль (S₀₄), `C02` → 24, `CaC03` → 76, `H20` → 20. Все с меткой «точно».
- Решение: индекс с ведущим нулём считать ошибкой распознавания. Предлагать замену 0 → O («Возможно, H₂SO₄?») и не ставить `exact`.
- Сложность: S. Статус: тест (QA, судья).

#### AUD-06. Ионные уравнения превращаются в молярную массу несуществующего вещества
- Источники: QA-6 (связано с QA-27: такие уравнения определяются как математика)
- Код: `ChemistrySolver.swift:167-185` (`solve`), `:490` (`findReaction`)
- Причина: заряды ионов не поддерживаются. Ветка «молярная масса» срабатывает без явной просьбы.
- Последствия: `Cu2+ + OH- = Cu(OH)2` → «M(Cu₂) = 128 г/моль» с меткой «точно».
- Решение: распознавать заряды и либо уравнивать с балансом заряда, либо честно отказывать. Молярную массу считать только по явному запросу («молярная масса», «M(…)»).
- Сложность: M. Статус: тест.

#### AUD-07. Сквозной перебор решателей: «точный» ответ даёт решатель чужого предмета
- Источники: QA-7, AI-4 (2 эксперта)
- Код: `AIHomework/Engine/Core/LocalSolverPipeline.swift:47-58` (`solve`, цикл `for engine in order(for:)`), `ChemistrySolver.swift:244` (`findFormulas`)
- Причина: если решатель выбранного предмета не справился, принимается любой `isSolved` следующего решателя. Химии достаточно одного токена, похожего на формулу.
- Последствия: `Fe + O2 = FeO + Fe2O3` → «Fe + O²» («упрощение выражения»). «В треугольнике ABC AB = 5, BC = 7…» → «M(BC) = 23 г/моль». Оба с меткой «точно».
- Решение: если решатель выбранного предмета узнал задание (вернул не `nil`), его результат окончательный. Чужие решатели принимать только при сильных признаках своего предмета.
- Сложность: S. Статус: тест (QA, судья).

#### AUD-08. Перевод систем счисления отбрасывает знак и дробную часть
- Источники: QA-8
- Код: `AIHomework/Engine/Text/InformaticsSolver.swift:98-101`, регулярное выражение `([0-9][0-9A-Fa-f]*|…)`
- Причина: в число не попадают «−» и «,» или «.».
- Последствия: −5 → «5₁₀ = 101₂», 0,5 → «0₂», 10,25 → «1010₂»: 7 из 7 проб неверны, все с меткой «точно».
- Решение: поддержать знак и дробную часть (умножение на основание с ограничением разрядов и «≈») или явно отказывать.

#### AUD-09. Номер задания попадает в данные
- Источники: AI-1 (воспроизведено судьёй)

- Последствия:

#### AUD-10. Решена только часть задания: «первое выражение», цепочка процентов, производная «в точке», НОД и НОК
- Источники: QA-9, AI-8 (2 эксперта)
- Код: `MathSolver.swift:737-842` (`solvePercent`), `:157` (примечание «решено первое»), `:116-118` (производная от первого кандидата), `:852+` (`solveDivisibility`)

#### AUD-11. Задания «про функцию» получают бессмысленный ответ
- Источники: AI-7
- Код: `MathSolver.swift:187-198, 215-224`, `EquationSolver.swift:567-618`, `SolutionModels.swift:161-166` (`isSolved` = «ответ не пустой»)
- Причина: намерение не распознаётся: «нули», «график», «наибольшее значение».
- Последствия: «Найдите нули функции f(x) = x² − 4x + 3» → «x² − 4x + 3» («уже в простом виде»). «Постройте график функции y = 2x + 1» → «x = 1/2·y − 1/2». Оба с меткой «точно» (судья). Без API задание не уходит к модели.
- Решение: «нули функции» сводить к `f(x) = 0`. «График», «наибольшее значение», «чётность» — честный отказ. Упрощение, которое ничего не изменило, считать `unsupported`.
- Сложность: M. Статус: тест (судья).

#### AUD-12. Эвристики OCR: `×` и пропавшая степень превращают квадратное уравнение в линейное
- Источники: AI-2, AI-6; связаны AI-9 и AI-20. Корень проблемы — жалоба владельца «x читается как ×»
- Код: `AIHomework/Engine/Math/MathLexer.swift:71-97` (`resolveTimesSign`), `:307-320` (`x2 → x²` только после буквы), `MathParser.swift:135-151` (неявное умножение после `)`)
- Причина: каждый `×` решается отдельно, без учёта остальных `×` в строке. Число после `)` считается множителем.
- Последствия: `2×2 − 5× + 2 = 0` (OCR-запись `2x² − 5x + 2 = 0`) → «x = 6/5», а `(x+1)2 = 9` → «x = 7/2». Оба с меткой «точно», без оговорки (судья).
- Решение:
  - если в строке хотя бы один `×` понят как переменная, считать переменными все `×`;
  - цифру 2…9 сразу после `)` читать как степень, с заметкой;
  - при любой эвристической правке ставить метку `heuristic`.
- Сложность: S. Статус: тест движка (судья). Что именно выдаёт Vision на `)²` и `x²` — устройство.

#### AUD-13. Определённый интеграл: верхний предел «прилипает» к подынтегральному выражению; расходящийся интеграл = 0
- Источники: AI-3, AI-18
- Код: `MathSolver.swift:583-587, 642-651`, `MathTextExtractor.swift:47-62`
- Причина: число предела остаётся в начале подынтегрального фрагмента. Для `ln|x|` не проверяется, лежит ли 0 внутри отрезка.
- Последствия, все с меткой «точно» (судья):
  - «интеграл от 0 до 2 x^2 dx» → 16/3 вместо 8/3;
  - «от 1 до 3 x dx» → 12 вместо 4;
  - `∫ 1/x dx от −1 до 1` → 0, хотя интеграл расходится.
- Решение: вырезать «от a до b» до вызова экстрактора и брать выражение между пределом и `dx`. Проверять разрывы подынтегральной функции на отрезке.
- Сложность: S. Статус: тест (судья).

#### AUD-14. Краш (SIGSEGV, переполнение стека) на длинных или глубоко вложенных выражениях
- Источники: QA-10
- Код: `AIHomework/Engine/Math/MathEvaluator.swift:73` (рекурсивный `eval`), `MathParser.swift:102` (`parseExpression`) → `:193` (`parsePrimary`), `Engine/Core/Deadline.swift:11-22`
- Причина: нет ограничения длины входа и глубины скобок. `Deadline.compute` защищает только от зависания, а не от падения. Лимит 2000 символов есть только в промптах для API (`TaskRouting.swift:60`), локальный решатель его не применяет.
- Последствия:
  - при стеке 512 КБ (как у фоновых потоков iOS) release-сборка падает на 3000 слагаемых `1+…+1` или на 2000 вложенных скобок;
  - падает всё приложение;
  - путь к такому входу: «Вставить из буфера» или ручной ввод.
- Решение: до разбора ограничить число токенов (≈500) и глубину скобок (≈64) с понятным отказом. Обход сделать итеративным или с ограничением глубины.
- Сложность: S. Статус: тест (Linux). Порог на iPhone — устройство.

#### AUD-15. Тексты о приватности обещают обработку на устройстве, а фрагмент фото уходит на сервер

#### AUD-16. Повторное решение перезаписывает запись истории: предыдущее задание теряется

#### AUD-17. Деление дробей через «:» разбирается как цепочка делений

#### AUD-18. Метка «Точное решение» не учитывает, кто прочитал условие; «точный» ответ не перепроверяется
- Источники: AI-10, QA-12; связано SEC-5
- Код: `Services/SolveCoordinator.swift:123-134, 146-153`, `DesignSystem/Theme.swift:131-132`
- Причина: метка описывает только вычисление. Условие, которое переписала нейросеть-диспетчер (`route.problem`) или OCR распознал с низкой уверенностью, всё равно получает «Вычислено точным алгоритмом на устройстве и проверено». Подмена условия видна только в примечании внизу.
- Последствия: все ошибки P0 доходят до пользователя с наивысшей меткой, и при подключённом API тоже.
- Решение:
  - отдельная подпись «Точное вычисление; условие переписано нейросетью / распознано с уверенностью N %»;
  - «Распознано как» показывать рядом с ответом;

## Решения, которые нужны от владельца

1. **Отправка фото в API.** Это противоречит правилу «не отправлять фото на внешние серверы» (SEC-1, AI-21, IOS-3). Сейчас при настроенном API фрагмент или весь снимок уходит в каждом задании, дважды.
   - Варианты:
     - (A) оставить как есть, но честно раскрыть и спросить согласие при настройке API;
     - (B) переключатель «Отправлять изображение», по умолчанию выключен: уходит только распознанный текст, а фото — по кнопке, когда OCR пуст или неуверен;
     - (C) как B, плюс подтверждение с превью каждый раз;
     - (D) фото только решателю, диспетчеру только текст;
     - (E) фото не покидает устройство никогда.
   - **Рекомендация судьи: B, а при включённом переключателе ещё и D.** B выполняет правило по умолчанию и оставляет качество на чертежах и рукописи тем, кто сознательно включил отправку. ## Что не проверялось

- Запуск на iPhone или симуляторе, а значит любое поведение интерфейса, анимаций, переходов, клавиатуры, VoiceOver и Dynamic Type.
- Реальные результаты Vision OCR: как он читает `x²`, `(x+1)²`, корни, дроби, рукопись. Все выводы о «×/x» и пропавших степенях основаны на коде и жалобе владельца.
- Apple Intelligence (FoundationModels): поддержка русского, реакция на отмену, качество ответов.
- Поведение apimira и конкретных моделей: зрение, `max_tokens`, «рассуждающие» модели, редиректы.
- Память и время на устройстве: пики при фото 48 Мп и при склейке сканера, подвисания главного потока. Все цифры PERF по UI — оценки, а замеры движка сделаны на Linux.
- Краш QA-10 в release-сборке на iPhone: точный порог зависит от реального размера стека потоков Swift Concurrency.
- Камера и разрешения: вид экрана при отказе в доступе, сканер VisionKit, системный запрос вставки.
- SwiftData: поведение `@Query` после пакетного удаления, судьба файлов `externalStorage`, класс Data Protection, попадание в iCloud-бэкап, миграции при обновлении через SideStore.
- Элемент управления iOS 18 и кнопка действия (холодный и тёплый запуск), фразы Siri.
- Предупреждения компилятора Xcode (Swift 6 strict concurrency) в журнале GitHub Actions. Сборка Codemagic.
- Поддержка поля `sha256` в SideStore, видимость репозитория и релиза.
- Соответствие светлой и тёмной темы эталону Linear (контраст посчитан только по hex-значениям).
