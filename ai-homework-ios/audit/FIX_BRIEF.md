| Вопрос | Решение |
|---|---|
| Отправка фото в API | Новая настройка «Отправлять изображение в нейросеть», **по умолчанию выключена**: в API уходит только текст. Если включена — изображение уходит **только в запрос решения**, не диспетчеру. Если текста нет (OCR пуст), а настройка выключена — честно объяснить и предложить включить настройку или ввести условие. |
| Фото в истории | «Сохранять фото в истории» — **по умолчанию выключено** для новых установок; кнопка «Удалить сохранённые фото»; файлы истории — с защитой данных и исключены из iCloud-бэкапа, где это применимо. |
| Решать сразу или показывать текст | Показывать экран проверки текста **только при низкой уверенности OCR** (или подозрительных символах вроде `×`), иначе решать сразу. |
| Сканер на несколько страниц | Не склеивать в полном разрешении на главном потоке: уменьшать в фоне; предпочтительно — распознавать постранично / дать выбрать страницу. |
| Мёртвый код «стеклянного» дизайна | Не удалять; пометить устаревшим (`@available(*, deprecated, ...)` или комментарий). |
| TestFlight/App Store | Пока только сайдлоад; `PrivacyInfo.xcprivacy` не добавлять. |

## Общие правила для исполнителей
- Источники: `PROJECT_AUDIT.md` (реестр AUD-xx с file:line, причиной и решением), `IMPROVEMENT_ROADMAP.md`, отчёты в `audit/*.md` (там конкретные входы и ожидаемые ответы).
- Не удалять файлы проекта, не переписывать без нужды, не менять архитектуру шире, чем требует исправление.
- Не добавлять платные API, авторизацию, сторонние зависимости.
- Движок: **сначала регрессионный тест** на каждый неверный ответ из аудита (вход → ожидаемый правильный ответ или честный отказ), потом исправление. Лучше честно не решить (`nil` / `unsupported`), чем выдать неверный ответ с меткой «Точное решение».
- Все тесты движка должны проходить: `swift test` в Docker `swift:6.2` (см. промпт исполнителя — у каждого свой том сборки).
- Код приложения (SwiftUI/UIKit) здесь не компилируется — писать особенно аккуратно: Swift 6 strict concurrency, iOS 17 deployment target (API iOS 18/26 — только под `#available`), следовать существующим паттернам проекта.
- Коммиты: **один файл — один коммит** (правило репозитория), сообщение `fix(ai-homework): ...` / `test(ai-homework): ...` / `feat(...)`, в конце строки:

  Без названий моделей в сообщениях и коде. Не пушить, не создавать PR.
