# Аудит AI/ML-части: распознавание и решение заданий

Эксперт: AI/ML Engineer. Метод: чтение кода и ручная трассировка. Тесты и Docker не запускались, на устройстве ничего не проверялось. Пути даны относительно `ai-homework-ios/AIHomework/`. Если не указано иное, «вход» — это текст, который попадает в `LocalSolverPipeline.solve` после OCR.

## Реальная функциональность

**Распознавание (OCR).** Используется `VNRecognizeTextRequest`: `.accurate`, языки `["ru-RU","en-US"]`, `minimumTextHeight = 0.008`, ревизия по умолчанию (`Services/OCRService.swift:71-76`). Сначала идёт проход с языковой коррекцией. Если доля цифр и знаков ≥ 0.18, делается второй проход без коррекции, и его результат полностью **заменяет** первый (`:48-57`). Фрагменты склеиваются в строки по `midY` на всю ширину кадра (`:102-114`). Перед OCR изображение приводится к ориентации `.up` и сжимается до 2600 px по длинной стороне. **Только после этого** из него вырезается выделенная область (`Features/Solve/SolveViewModel.swift:130-131`, `Services/ImageTools.swift:18-47`). Структуру формул Vision не видит. Дробь «в столбик» превращается в несколько строк, надстрочные индексы — в обычные цифры (`x2`), черта над корнем теряется. Средняя уверенность OCR считается (`OCRService.swift:116`), но на решение не влияет. После распознавания решение запускается сразу, без шага проверки текста (`SolveViewModel.swift:160-165`).

**Нормализация математики.** Кириллические «двойники» заменяются на латиницу (`Engine/Math/MathLexer.swift:55-58`). `×` считается переменной `x`, если не стоит между двумя операндами (`:71-97`). `x2 → x²` для одиночной цифры 2…9 после буквы, с пометкой в решении (`:307-320`). Есть нормализация `≤ ≥ − ÷ ½`. Парсер работает рекурсивным спуском с неявным умножением (`MathParser.swift:117-151`). Экстрактор `MathTextExtractor` отделяет формулы от слов.

**Точные решатели (детерминированные, без ИИ):**
- арифметика в рациональных числах с переходом в `Double` при переполнении;
- линейные, квадратные, биквадратные уравнения и многочлены: рациональные корни плюс численный остаток;
- дробно-рациональные уравнения с ОДЗ, параметрические линейные уравнения;
- уравнения с корнями, модулем, `log` и тригонометрией — численно на [−1000; 1000] или на [0; 2π) с уточнением до рационального числа или `kπ`;
- неравенства методом интервалов (рациональные) и двойные линейные;
- системы: линейные (до 4×4, Гаусс) и нелинейные 2×2 подстановкой;
- производная символьно, интеграл многочленов и табличных функций (`sin, cos, eˣ, 1/x`), определённый интеграл;
- упрощение, разложение на множители, подстановка значений, проценты (5 шаблонов), НОД/НОК/простые множители.

Кроме математики:
- физика: задачи «в одну формулу», метка `heuristic`;
- химия: молярная масса, массовые доли, количество вещества, уравнивание реакций через нуль-пространство матрицы;
- информатика: системы счисления, единицы информации (1024).

**Определение предмета.** Словарь основ слов с весами плюс структурные признаки: плотность символов, формулы, физические величины, химические формулы (`Engine/Text/SubjectDetector.swift:276-339`). Если определён гуманитарный предмет, точные решатели не вызываются совсем (`Engine/Core/LocalSolverPipeline.swift:33`).

**Языковые модели.**
- С API пользователя. Первый запрос — «диспетчер» (JSON, `max_tokens = 400`, тайм-аут 25 с) с картинкой и текстом. Он выбирает `local` (переписывает условие для точного решателя) или `model`. Второй запрос — полное решение (тайм-аут 75 с, формат «ОТВЕТ / ОБЪЯСНЕНИЕ / ШАГИ») (`Services/SolveCoordinator.swift:108-197`).
- Без API: точный решатель, затем Apple Intelligence (FoundationModels, только текст, `temperature 0.3`), затем честный отказ.
- Core ML-моделей в проекте нет.

**Метки достоверности.** `exact` показывается как «Точное решение» с подписью «Вычислено точным алгоритмом на устройстве и проверено» (`DesignSystem/Theme.swift:120,132`). Ответы нейросети получают `generated`. Метка выставляется только по типу решателя. Уверенность OCR и то, что условие переписала нейросеть, на неё не влияют.

## Сильные стороны

1. **Честная архитектура «вычисляет алгоритм, читает нейросеть».** Диспетчер переписывает условие, точный решатель считает. Так нейросеть не «галлюцинирует» в арифметике (`Engine/Core/TaskRouting.swift:22-27`, `SolveCoordinator.swift:123-135`). Переписанное условие показывается в заметке.
2. **Проверка корней подстановкой в исходное уравнение.** Есть в `EquationSolver.finish` (`Engine/Math/EquationSolver.swift:731-766`). Посторонние корни и корни вне ОДЗ после сокращения отсеиваются надёжно, потому что проверка идёт по исходным выражениям, а не по упрощённым. Системы тоже проверяются (`SystemSolver.swift:255`).
3. **Точная арифметика.** Рациональные числа с контролем переполнения, корни вида `p + q√n`, значения тригонометрии `kπ` по теореме Нивена (`MathEvaluator.swift:266-307`). Используются метки `approximate` и `exact` по смыслу.
4. **Надёжный численный поиск корней многочлена.** Корни ищутся между критическими точками рекурсивно, кратные корни ловятся через производную (`Algebra.swift:240-302`).
5. **Уравнивание реакций через нуль-пространство** с проверкой единственности и знаков (`ChemistrySolver.swift:571-613`), а не перебором.
6. **Честные отказы.** Неоднозначность формул в физике ведёт к отказу (`PhysicsSolver.swift:73-78`). Все данные условия должны быть использованы (`:299-301`). Гуманитарные числа (даты) не вычисляются. Явно сообщается, что нейросеть недоступна.
7. **Защита от зависаний.** Лимит 6 с на точный решатель, общий тайм-аут на все попытки API, одна повторная попытка при обрыве сети.
8. **Тест-проверка на совместимость.** Примеры записей диспетчера должны решаться точным решателем (`EngineTests/TaskRoutingTests.swift:47-67`).

## Находки

### AI-1. Номер задания попадает в данные (НОД/НОК, простые множители, системы счисления)
- Приоритет: P0
- Файл: `Engine/Math/MathSolver.swift:864-866, 867`; `Engine/Text/InformaticsSolver.swift:97-104`
- Место в коде: `solveDivisibility` собирает **все** числа из текста (`Rx.matches("(?<![\\d.,])\\d{1,12}(?![\\d.,]\\d)", in: lower)`). Для разложения на простые множители берётся `numbers.first`. В информатике берётся «первая цифровая запись».
- Причина: `stripNumbering` применяется только в `MathTextExtractor`, а эти решатели работают с сырым текстом.
- Последствия: на фото страницы учебника почти всегда есть «№ 245.» или «3.». Трассировка:
  - «3. Найдите НОД чисел 12 и 18» → НОД(3; 12; 18) = 3 вместо 6;
  - «№ 12. Разложите на простые множители число 360» → «12 = 2²·3»;
  - «№ 5. Переведите число 45 в двоичную систему» → переводится 5.

  Всё это идёт с меткой «Точное решение».
- Решение: перед этими шаблонами убирать нумерацию (`^\s*(№\s*)?\d+[.)]`, «Задание N»). Числа брать после ключевых слов («чисел», «число», «of»). Если чисел больше, чем ожидается, — отказ, а не вычисление.
- Сложность: S
- Статус проверки: проверено чтением кода; нужен тест на входах выше.

### AI-2. `×` между цифрами при пропавшей степени: «2×2−5×+2=0» решается как линейное уравнение
- Приоритет: P0
- Файл: `Engine/Math/MathLexer.swift:71-97`
- Место в коде: `resolveTimesSign` превращает каждый `×` в умножение, если по обе стороны стоят операнды, независимо от других `×` в той же строке.
- Причина: на устройстве OCR читает `x` как `×` (жалоба владельца) и теряет надстрочную `²`. Запись `2x²−5x+2=0` становится `2×2−5×+2=0`. Первый `×` получает `*`, второй — `x`. Выходит `4 − 5x + 2 = 0`.
- Последствия: ответ `x = 6/5` с меткой «Точное решение» вместо `x₁ = 1/2; x₂ = 2`. Заметки про `x2 → x²` нет.
- Решение: если в строке есть хотя бы один `×`, распознанный как переменная, считать все `×` переменными (и применять `x2 → x²` с заметкой). `×` между цифрами без других признаков оставить умножением, но добавить заметку о двусмысленности. Также передавать в результат флаг «условие исправлено эвристикой» и понижать метку до `heuristic`.
- Сложность: S
- Статус проверки: проверено чтением кода; нужен тест `MathSolver.solve("2×2 − 5× + 2 = 0")`, ожидается `x₁ = 1/2; x₂ = 2` или явная оговорка.

### AI-3. Определённый интеграл: верхний предел «прилипает» к подынтегральному выражению
- Приоритет: P0
- Файл: `Engine/Math/MathSolver.swift:583-587, 642-651`; `Engine/Math/MathTextExtractor.swift:47-62`
- Место в коде: экстрактор склеивает соседние математические токены через пробел. «… от 0 до 2 x^2 dx» даёт фрагменты `0` и `2 x^2 dx`. Предел берётся регулярным выражением, а подынтегральное выражение `2 x^2` парсится как `2·x²`.
- Причина: числа, уже использованные как пределы, не исключаются из фрагмента.
- Последствия: «Вычислите интеграл от 0 до 2 x^2 dx» → 16/3 вместо 8/3. «Вычислите интеграл от 1 до 3 x dx» → 12 вместо 4. Метка «Точное решение».
- Решение: удалять из текста совпадение `от a до b` до вызова экстрактора, либо отрезать у фрагмента ведущее число, равное пределу. Лучше брать подынтегральное выражение между `∫`/пределом и `dx`.
- Сложность: S
- Статус проверки: требует теста. Входы: «Вычислите интеграл от 0 до 2 x^2 dx» → 8/3; «Вычислите интеграл от 1 до 3 x dx» → 4.

### AI-4. Сквозной перебор решателей: геометрическая задача получает «молярную массу BC»
- Приоритет: P0
- Файл: `Engine/Core/LocalSolverPipeline.swift:47-58`; `Engine/Chemistry/ChemistrySolver.swift:178-186, 235, 244-258`
- Место в коде: если решатель предмета вернул «не решено», конвейер идёт дальше, вплоть до химии. `findFormulas` принимает обозначение отрезка `BC` (B + C) или `CO` за формулу. Затем `molarMass(formula)` выдаёт ответ.
- Причина: решатель «чужого» предмета не обязан доказывать, что задание его. Химии достаточно одного токена, похожего на формулу.
- Последствия: офлайн или при сбое API вход «В треугольнике ABC AB = 5, BC = 7, AC = 6. Найдите периметр» даёт по трассировке: математика не решает (нелинейная система из 3 переменных), физика ничего не находит, химия отвечает «M(BC) = 23 г/моль» с меткой «Точное решение».
- Решение:
  - решатель другого предмета принимать только при сильных признаках (для химии — `evidence != .none` или ключевые слова «молярн», «вещество»);
  - если решатель основного предмета узнал задание и не справился, дальше не идти;
  - добавить `ChemistrySolver.falseFormulas`-эвристику для заглавных пар в геометрическом контексте («треугольник», «отрезок»).
- Сложность: S
- Статус проверки: проверено чтением кода (ветки); нужен тест `LocalSolverPipeline(lang:.ru).solve("В треугольнике ABC AB = 5, BC = 7, AC = 6. Найдите периметр.", subject: .math)`, ожидается не решено.

### AI-5. Тождество на ОДЗ: «(x²−9)/(x−3) = x+3» → «Действительных корней нет»
- Приоритет: P0
- Файл: `Engine/Math/EquationSolver.swift:484-563` (ветка `degree == 0` на `:525-526`)
- Место в коде: после приведения к общему знаменателю числитель тождественно равен 0. `candidates = []`, а `finish` отвечает «Действительных корней нет».
- Причина: случай «нулевой числитель» не отличается от «ненулевой константы». Для многочленов этот случай обработан (`:145-167`), для дробей — нет.
- Последствия: классические задачи «на ловушку ОДЗ» получают неверный ответ с меткой «Точное решение». Сюда же относится `x/x = 1`.
- Решение: если числитель равен нулю, ответить «x — любое число, кроме …» (исключённые корни знаменателя). В неравенствах это уже сделано (`InequalitySolver.swift:110-124`).
- Сложность: S
- Статус проверки: проверено чтением кода. Тест: «(x^2 − 9)/(x − 3) = x + 3» → «x ≠ 3, x — любое другое число»; «x/x = 1» → «x ≠ 0».

### AI-6. Пропавшая степень после скобки: «(x+1)2 = 9» решается как 2(x+1) = 9
- Приоритет: P1
- Файл: `Engine/Math/MathLexer.swift:259-321`; `Engine/Math/MathParser.swift:135-151`
- Место в коде: эвристика `x2 → x²` есть только после буквы. После `)` число означает неявное умножение.
- Причина: Vision читает `(x+1)²` как `(x+1)2`.
- Последствия: ответ `x = 7/2` с меткой «Точное решение» вместо `x₁ = −4; x₂ = 2`, без оговорок.
- Решение: число 2…9 сразу после `)` без пробела читать как степень, с той же заметкой «прочитано как степень».
- Сложность: S
- Статус проверки: требует теста (вход выше) и проверки на устройстве (как Vision на самом деле читает `)²`).

### AI-7. Задания «про функцию» дают бессмысленный ответ с меткой «Точное решение»
- Приоритет: P1
- Файл: `Engine/Math/MathSolver.swift:187-198, 215-224`; `Engine/Math/EquationSolver.swift:567-618`
- Место в коде: `f(x) = …` без глагола показывает упрощение правой части. `y = 2x + 1` идёт в `EquationSolver` с выбором переменной `x` и получает параметрический ответ.
- Причина: намерение («найдите нули», «постройте график», «наибольшее значение», «область определения») не распознаётся. Любой ответ с непустым `answer` считается решённым (`SolutionModels.swift:161-166`), поэтому офлайн переход к модели не происходит.
- Последствия: «Постройте график функции y = 2x + 1» → «x = ½y − ½». «Найдите нули функции f(x) = x² − 4x + 3» → «x² − 4x + 3» с заметкой «уже в простом виде». В обоих случаях метка «Точное решение».
- Решение:
  - «нули функции» → решать `f(x) = 0` (уже реализуемо);
  - «график», «наибольшее значение», «чётность» → честный отказ;
  - упрощение, которое ничего не изменило, считать `unsupported` (тогда задание уйдёт к модели).
- Сложность: M
- Статус проверки: проверено чтением кода; тестовые входы выше.

### AI-8. Частичный ответ с меткой «Точное решение»: производная «в точке», цепочки процентов, несколько чисел
- Приоритет: P1
- Файл: `Engine/Math/MathSolver.swift:116-118, 737-842, 892-919`
- Место в коде: производная берётся только от `candidates[0]`, «в точке x₀» игнорируется. Проценты: возвращается первое совпадение шаблона. НОД/НОК берётся от всех чисел сразу.
- Последствия:
  - «Найдите значение производной функции f(x) = x³ − 2x в точке x₀ = 2» → `f′(x) = 3x² − 2` (нужно 10);
  - «Найдите 20% от 50% от 400» → 10 (нужно 40);
  - «Увеличьте 200 на 15%, затем уменьшите результат на 10%» → 230 (нужно 207);
  - «Найдите НОД чисел 24 и 36 и НОК чисел 8 и 12» → НОД(24; 36; 8; 12) = 4.
- Решение: если в тексте остались неиспользованные числа или связки («затем», «в точке», «и НОК чисел»), отдавать `unsupported` (или `heuristic` с заметкой «решена только часть»). Отдельно — подстановку в производную.
- Сложность: M
- Статус проверки: проверено чтением кода; нужен тест на входах выше.

### AI-9. Корень без скобок: OCR теряет черту над корнем, «√(x+3)» превращается в «√x+3»
- Приоритет: P1
- Файл: `Engine/Math/MathParser.swift:288-300`

### AI-10. Метка «Точное решение» не учитывает, кто прочитал условие

### AI-11. Любой сбой диспетчера отключает API для всего решения

- Файл: `Services/SolveCoordinator.swift:140-144, 160`; `Engine/Core/TaskRouting.swift:30`; `Engine/Core/RemoteAPI.swift:134-148`
- Место в коде: `catch { remoteUsable = false }`. После этого полное решение по API не запрашивается.

  1. модель без зрения → HTTP 400 на `image_url`;
  2. «рассуждающие» модели расходуют `max_tokens = 400` на рассуждение → пустой `content` → `emptyResponse`;

### AI-13. Apple Intelligence как офлайн-решатель почти недоступен русскоязычному ученику

## Рекомендации по развитию AI-части

1. **Сначала исправить P0 (AI-1…AI-5) и добавить входы из таблицы выше в `EngineTests` как регрессионный набор.** Тесты должны проверять сам ответ, а не только `isSolved`. Работа небольшая (S), а снимает самые опасные «уверенные» ошибки.
2. **Ввести «границу уверенности» решателя.** Решатель обязан доказать, что задание его: все числа использованы, нет связок вида «затем», «в точке», «и …». Иначе он отвечает `unsupported` и задание уходит к нейросети. Это закрывает AI-4, AI-7, AI-8 одним механизмом.
3. **Честные метки по источнику условия.** «Точное вычисление» плюс отдельный индикатор «условие: набрано / распознано (уверенность N %) / переписано нейросетью». При низкой уверенности OCR — обязательный шаг проверки текста.
4. **Сделать диспетчер устойчивым** (AI-11): классифицировать ошибки, повторять без картинки и без `max_tokens`, `temperature: 0`, разделитель систем «; ». Рассмотреть один запрос вместо двух (модель сразу возвращает либо `{"route":"local",…}`, либо решение) — это вдвое меньше задержка и трафик картинки.
5. **Промпт решения «рассуждение → ответ»** (AI-12) и собрать небольшой оценочный набор (30–50 заданий РФ 5–11 класс с эталонами), чтобы сравнивать модели apimira по точности и цене, а не на глаз.
6. **Apple Intelligence — в роли офлайн-«нормализатора».** Использовать `@Generable`-структуру `TaskRoute` с английскими инструкциями: модель только переписывает условие, считает точный решатель. Если язык не поддерживается, не показывать её как доступную (AI-13).
7. **OCR:** обрезка до масштабирования и увеличение мелких фрагментов (AI-14), раздельные проходы для текста и формул, группировка по колонкам, `en-US` для формул (AI-15). Оценить `RecognizeDocumentsRequest` (iOS 26).
8. **Локальная модель распознавания формул (категория 2), если нужен офлайн без API.** Небольшая im2latex-модель (TexTeller / Pix2Text-MFR, ~100–300 МБ) в Core ML, скачивание при первом запуске, а не в .ipa. Она снимает целый класс ошибок (дроби, степени, корни) лучше эвристик. Полноценная локальная LLM-решательница (1.5–3B) реалистична по памяти только в варианте ~1.5B 4 бит и слаба в русском. Без явного запроса владельца не рекомендую.
9. **Расширить алгоритмическую часть (категория 1),** а не «ИИ»: неравенства с корнями и логарифмами, «производная в точке», нули и ОДЗ функции, интегрирование подстановкой для типовых школьных случаев, геометрия по формулам (периметр, площадь, теорема Пифагора) с меткой `heuristic`.
10. **Решить с владельцем вопрос AI-21** (отправка изображений) и отразить выбранный вариант в интерфейсе настроек.
