# Аудит UI/UX — AI Homework (iOS)

Эксперт: UI/UX Designer. Область: `AIHomework/DesignSystem/*`, `AIHomework/Features/**`, `Services/Haptics.swift`, локализация.
Метод: чтение кода SwiftUI (собрать и запустить приложение в этой среде нельзя). Контраст посчитан по формуле WCAG 2.x
из hex-значений `Palette` (`Theme.swift:34-53`). Всё, что зависит от рендеринга, помечено «требует визуальной проверки».
Эталон: `awesome-design-md/design-md/linear.app/DESIGN.md` (монохром, один акцент `#5e6ad2`, плоские поверхности, тонкие рамки).

## Оценка

**Итог: 6/10.** Визуальный язык Linear перенесён аккуратно и в основном последовательно. Минусы: доступность
(Dynamic Type, контраст третичного текста, «Уменьшение движения», VoiceOver), а в основном сценарии нет контроля
над распознанным текстом и над долгим ожиданием.

| Критерий | Балл | Обоснование |
|---|---|---|
| Соответствие Linear (монохром + 1 акцент, плоскость) | 8 | Токены `Palette` точно повторяют DESIGN.md (canvas `#010102`, surface `#0F1011…#18191A`, hairline `#23252A`, ink `#F7F8F8`). Теней нет, атмосферных градиентов нет (`AnimatedBackground.swift:11`). Отступления: зелёный `success` как второй цвет почти на каждом экране (UX-14), системные списки и формы со своими серыми поверхностями (UX-8), во второй акцентный тон `#828FFF` перекрашены системные элементы (UX-8). |
| Иерархия и типографика | 6 | Лестница заголовков задана (`Theme.swift:80-84`), но на экране результата самый крупный жирный заголовок — имя модели, а не ответ (UX-13). Радиусы местами захардкожены (UX-23). |
| Доступность (Dynamic Type, контраст, VoiceOver, Reduce Motion) | 3.5 | Заголовки и подписи кнопок не масштабируются (UX-2). `inkTertiary` даёт 2.6:1 в светлой теме и 3.6:1 в тёмной (UX-6). Тост об ошибке показывается с зелёной галочкой (UX-12). |

Hero-переход орба, скорее всего, выглядит как перелёт с подменой картинки, а не морфинг (UX-15). Тактильных откликов слишком много, есть двойные (UX-11). |

| Уровень по сравнению с коммерческими AI | 4.5 | Нет отрисовки формул, follow-up вопросов, потокового вывода, «объясни проще», копирования всего решения (раздел ниже). |

## Сильные стороны

1. **Токены цвета дисциплинированы.** Все экраны красятся через `Palette`. Системный `.secondary` и «сырые»
   `Color.red/blue` в UI не встречаются: grep нашёл только `Color.white/black` в оправданных местах — затемнение
   вокруг выделения на фото (`RegionSelectionView.swift:36`), подложка следа пальца (`:58`), маркеры (`:156`).
   Светлый и тёмный варианты заданы парами в `Color(light:dark:)` (`Theme.swift:17-27`).
2. **Поверхности по правилам Linear.** `SurfaceStyle` (`GlassSurface.swift:8-43`) строит иерархию так, как в DESIGN.md:
   три уровня заливки, рамка 1 pt и едва заметный блик сверху, без теней и размытия. Выбранный чип «приподнят»
   поверхностью, а не цветом (`Components.swift:61-110`).
3. **Акцент экономный и осмысленный.** Сплошной акцент есть только у главной кнопки (`Buttons.swift:47-54`) и у CTA
   на главном экране (`HomeView.swift:104-107`). В карточке ответа это тонкая полоса 2 pt (`SolutionContentView.swift:120-126`).
   Именно так в Linear: «accent never decorative».
4. **Спокойное движение.** Пружины `dampingFraction 0.92/0.95` без заметного отскока (`Theme.swift:73-75`). Каскадная задержка
   ограничена 0,5 с (`Components.swift:239`). Анимация сканирования не мелькает: распознавание держится минимум 0,9 с
   (`SolveViewModel.swift:146-147`). Индикатор решения тоже не мелькает: минимум 0,8 с (`SolveViewModel.swift:277-278`).
5. **Честная прозрачность пути решения.** Стадия «Решаю» показывает реальные этапы: диспетчер → точный решатель → модель
   (`SolveFlowView.swift:274-333`). Метка достоверности подписана текстом, а не только цветом (`Components.swift:130-145`,
   `Theme.swift:118-146`). Этого нет у большинства конкурентов.
6. **Продуманные служебные состояния.** Пустая история с CTA (`HistoryView.swift:110-119`), пустой поиск
   (`HistoryView.swift:120`), подтверждение очистки истории (`HistoryView.swift:137-143`), удаление по свайпу и через
   контекстное меню, группировка по дням.
7. **Безопасная зона и плавающие панели.** Панель действий результата и кнопка «Решить» стоят в `safeAreaInset(edge: .bottom)`
   (`SolveStages.swift:37-45, 218-220`), поэтому не налезают на индикатор «домой». `scrollDismissesKeyboard(.interactively)`
   (`SolveStages.swift:36`).

## Находки

### UX-1. Распознанный текст уходит на решение без проверки, даже при низкой уверенности OCR
- Приоритет: P1
- Файл: `AIHomework/Features/Solve/SolveViewModel.swift:150-165`; `AIHomework/Features/Solve/RegionSelectionView.swift:128-134`; `AIHomework/Features/Solve/SolveStages.swift:93-114`
- Место в коде: в `recognize(useSelection:)` после OCR сразу вызывается `solve(context:)` (`if let modelContext { solve(...) }`); стадия `.review` с рамками строк и строкой уверенности достижима только через «Изменить» на экране результата. Лассо запускает распознавание через 350 мс после отрыва пальца.
- Причина: стремление к поведению Circle to Search («обвёл — решаю») применено безусловно.
- Последствия: известная жалоба владельца «x читается как ×» превращается в неверное решение (и платный запрос в API) раньше, чем пользователь видит текст. Экран проверки с процентом уверенности (`confidenceRow`) практически никто не увидит. Угловые маркеры при первом выделении бесполезны: стадия меняется через 0,35 с.
- Решение: в `recognize` переходить в `.review`, если `result.averageConfidence < 0.85` или `usedMathPass == true` (формулы — главный источник ошибок); иначе автозапуск. В `ReviewStage` при автопереходе сделать кнопку «Решить» с обратным отсчётом (3 с, отменяется касанием поля) — сохраняет «одно касание» и даёт шанс исправить. Опционально: настройка «Всегда проверять текст» в разделе «Основное».
- Сложность: S
- Статус проверки: проверено чтением кода

### UX-2. Dynamic Type не работает для заголовков и кнопок; фиксированные размеры ломают раскладку при крупном шрифте
- Приоритет: P1
- Файл: `AIHomework/DesignSystem/Theme.swift:80-84`; `AIHomework/DesignSystem/Buttons.swift:40,46,73,79,97`; `AIHomework/Features/Solve/SolveStages.swift:270`; `AIHomework/Features/Home/HomeView.swift:103,322`
- Место в коде: `Font.system(size: 32/26/20/17/15)` для `displayLarge…buttonLabel`; `.frame(height: 50)` и `.frame(height: 46)` у кнопок; `RecentCard` с `.frame(width: 210, height: 150)`.
- Причина: в токенах шрифтов размеры заданы в пунктах без привязки к текстовому стилю.
- Последствия: при «Крупном тексте» / AX-размерах подписи (`.subheadline`, `.caption`) растут, а заголовки карточек, стадий и все кнопки остаются 15–17 pt — иерархия переворачивается. Текст `RecentCard` вылезает за фиксированную рамку 150 pt, потому что обрезки нет. Нарушение HIG и проверка доступности App Store (если когда-нибудь понадобится).
- Решение: переписать токены через стили: `displayLarge = .system(.largeTitle, weight: .semibold)`, `displayMedium = .system(.title, weight: .semibold)`, `headlineTitle = .system(.title3, weight: .semibold)`, `cardTitle = .system(.headline, weight: .medium)`, `buttonLabel = .system(.subheadline, weight: .medium)`. Иконки — `.font(.body)`/`.imageScale`. В кнопках `.frame(minHeight: 50)` вместо `height`; в `RecentCard` — `@ScaledMetric var cardWidth = 210` и `minHeight`. Для AX-размеров — `ViewThatFits`/`dynamicTypeSize(...DynamicTypeSize.accessibility2)` на плитках главного экрана.
- Сложность: M
- Статус проверки: проверено чтением кода; поведение раскладки на AX5 требует визуальной проверки

### UX-3. Стадия «Решаю»: нет отмены с возвратом к условию; ожидание до ~2,5 мин без пояснений
- Приоритет: P1
- Файл: `AIHomework/Features/Solve/SolveFlowView.swift:270-317`; `AIHomework/Services/RemoteAPIProvider.swift:24-26`; `AIHomework/Services/SolveCoordinator.swift:36-38`
- Место в коде: в `SolvingStage` только орб, счётчик `"\(elapsed) с"` (`inkTertiary`) и список этапов. Единственный выход — `xmark` в верхней панели, который закрывает весь сценарий (`app.closeFlow()`, изображение теряется). Лимиты: диспетчер 25 с + точный 6 с + API 75 с + Apple Intelligence 60 с ≈ 166 с в худшем случае.
- Причина: защиту от «бесконечного решения» сделали на уровне сервиса, а в UI её не продолжили.
- Последствия: пользователь, который уже жаловался на «бесконечно решает», снова видит растущий счётчик без кнопки «Остановить». Закрыть сценарий значит заново фотографировать и выделять.
- Решение: под карточкой этапов добавить `GlassButton("Остановить", systemImage: "stop.fill")`. Он вызывает `model.cancel()` и `setStage(.review)`, текст и фото сохраняются. С 15 с показывать подсказку `inkSubtle`: «Модель отвечает дольше обычного…», с 40 с — второе действие «Решить без нейросети» (только точный решатель). Счётчик красить `inkSubtle`, а не `inkTertiary` (см. UX-6).
- Сложность: S
- Статус проверки: проверено чтением кода

### UX-4. Ошибка сети/таймаута: настоящая причина спрятана внизу, главный CTA ведёт не туда
- Приоритет: P1
- Файл: `AIHomework/Features/Solve/SolutionContentView.swift:127-151, 59-61, 197-225`; `AIHomework/Features/Solve/SolveStages.swift:206-210`; `AIHomework/Services/SolveCoordinator.swift:141-145, 199-205`
- Место в коде: при ошибке API причина («Сетевое соединение потеряно», «Модель не ответила вовремя») дописывается в `solution.notes`. Заметки выводятся последней карточкой (`notesCard`, `.staggered(7)`) мелким `footnote`. Карточка «Ответа нет — и это честно» показывает `limitationMessage` и кнопку «Настроить нейросеть», которая передаётся всегда (`onOpenModels` не nil).
- Причина: на экране результата нет отдельного состояния «ошибка доставки» — оно сведено к «не решено».
- Последствия: API настроен, пропал интернет — пользователь читает «нужна нейросеть» и идёт в настройки, где всё правильно. Ровно та путаница, о которой сообщал владелец. «Заново» стоит в нижней панели как равноправная иконка, а не как главное действие.
- Решение: в `SolveOutcome` различать `failure(kind: .network | .timeout | .auth | .notConfigured)`. Для `.network/.timeout` карточка: иконка `wifi.exclamationmark` (`inkMuted`), заголовок «Нет связи с нейросетью», текст причины, `PrimaryButton("Повторить")`, вторичная `GlassButton("Решить на устройстве")`, если доступна Apple Intelligence. «Настроить нейросеть» показывать только при `.notConfigured/.auth`. Сохранять в историю только с пометкой и без дублей.
- Сложность: M
- Статус проверки: проверено чтением кода

### UX-5. В истории «Решить заново» и «Изменить и решить» сразу решают, теряют фото и могут отправить заглушку
- Приоритет: P1
- Файл: `AIHomework/Features/History/ProblemDetailView.swift:58-60, 97-101`; `AIHomework/Features/Solve/SolveViewModel.swift:65-69, 283`
- Место в коде: оба действия вызывают `app.startSolve(.text(problem.problemText, subject:))`. Для непустого текста `init` ставит `stage = .solving` и `shouldAutoSolve = true`. Задание, решённое по картинке без OCR-текста, сохранено с текстом-заглушкой «Задание на изображении».
- Причина: из истории нет входа в стадию проверки и нет передачи сохранённого изображения.
- Последствия: пункт «Изменить и решить» ничего не даёт изменить. Повтор задачи-картинки отправит в API строку «Задание на изображении» без картинки и вернёт бессмыслицу. Каждый такой повтор создаёт новую запись в истории.
- Решение: добавить `SolveInput.restored(text:, image: Data?, subject:, autoSolve: Bool)`. «Решить заново» → `autoSolve: true` с изображением из `problem.imageData`. «Изменить и решить» → `autoSolve: false`, сразу `.review` с фокусом в редакторе. Заглушку хранить в отдельном поле (`isImageOnly`), а не в `problemText`.
- Сложность: S
- Статус проверки: проверено чтением кода

### UX-6. Третичный текст не проходит контраст WCAG AA
- Приоритет: P2
- Файл: `AIHomework/DesignSystem/Theme.swift:50`; использование — `HomeView.swift:262-263`, `SolveFlowView.swift:287-289`, `HistoryView.swift:213-217`, `SolutionContentView.swift:211-219`, `SolveStages.swift:164-165`, `ProblemDetailView.swift:139-141`
- Место в коде: `inkTertiary = Color(light: 0x9A9EA5, dark: 0x62666D)` используется для текста (подвал о приватности, счётчик секунд, «Не решено», время в строке истории, плейсхолдер редактора, «Решено нейросетью по API»).
- Причина: в DESIGN.md `ink-tertiary` — цвет для декоративных подписей на маркетинговом полотне, а здесь он стоит на функциональном тексте 11–12 pt.
- Последствия: расчёт: светлая тема — 2,60:1 на canvas, 2,69:1 на surface1; тёмная — 3,62:1 / 3,30:1 (нужно ≥4,5:1 для мелкого текста). Шевроны (`HomeView.swift:216-218`) в светлой теме ниже 3:1 для нетекстовых элементов. `success` в светлой теме на белом — 4,42:1, тоже чуть ниже нормы.
- Решение: для любого текста использовать минимум `inkSubtle` (4,9:1 светлая / 6,4:1 тёмная); `inkTertiary` оставить для иконок-разделителей и неактивных состояний. Либо затемнить светлый `inkTertiary` до `0x7C8088`, а тёмный осветлить до `0x7A7F87`. `success` в светлой теме — `0x1A7A33`.
- Сложность: S
- Статус проверки: проверено чтением кода (расчёт по hex); отображение требует визуальной проверки

### UX-7. Светлая тема: карточки почти сливаются с фоном
- Приоритет: P2
- Файл: `AIHomework/DesignSystem/Theme.swift:39-45`
- Место в коде: `canvas 0xFBFBFC` и `surface1 0xFFFFFF` (контраст 1,03:1), `hairline 0xE6E7EA` (1,2:1 к фону). Блик сверху `Color.white.opacity(0.06)` (`GlassSurface.swift:33-35`) на белом не виден.
- Причина: DESIGN.md Linear описывает только тёмную тему; светлую вывели «зеркально», без собственной лестницы.
- Последствия: в светлой теме весь экран — белое полотно с едва заметными линиями. Плитки быстрых действий, карточки предметов и шагов читаются как текст без контейнеров, иерархия теряется. Особенно на ярком солнце.
- Решение: светлая лестница как в светлом Linear: `canvas 0xF4F5F7`, `surface1 0xFFFFFF`, `surface2 0xF7F8F9`, `surface3 0xEEF0F2`, `hairline 0xDFE1E5`, `hairlineStrong 0xC9CCD2`. Блик в светлой теме заменить тонкой нижней рамкой `hairline` или убрать.
- Сложность: S
- Статус проверки: требует визуальной проверки (расчёт контраста — по коду)

### UX-8. Системные списки, формы и цвет акцента не согласованы с Palette
- Приоритет: P2
- Файл: `AIHomework/Features/History/HistoryView.swift:39-43, 104-106, 117`; `AIHomework/Features/Settings/SettingsView.swift:67-69`; `AIHomework/Resources/Assets.xcassets/AccentColor.colorset/Contents.json`
- Место в коде: `List(.insetGrouped)` и `Form` со скрытым фоном, но строки на системном `secondarySystemGroupedBackground` (`#1C1C1E` в тёмной теме) — светлее всех поверхностей Linear (`#0F1011…#18191A`). Системный сегментированный `Picker` над кастомными `FilterChip`. `AccentColor` в тёмной теме — `#828FFF`, а `Palette.accent` — `#5E6AD2`. Кнопка `.borderedProminent` в пустой истории даёт белый текст на `#828FFF` — 2,87:1.
- Причина: экраны на системных контейнерах не довели до токенов.
- Последствия: в тёмной теме история и настройки выглядят как другое приложение: серые «iOS-плашки» среди чёрных Linear-карточек. Два разных синих в одном интерфейсе. Главная кнопка пустого состояния нечитаема по контрасту.
- Решение: `.listRowBackground(Palette.surface1)` и `.listRowSeparatorTint(Palette.hairline)` для строк, `.listSectionSeparator(.hidden)`; заголовки секций — `Palette.inkSubtle`. В `AccentColor` для тёмной темы поставить `#5E6AD2` (как `Palette.accent`), `#828FFF` оставить только для `accentHover`. В пустой истории — `PrimaryButton`. Сегменты «Все/Избранное» заменить двумя `FilterChip` в общем ряду с предметами.
- Сложность: S
- Статус проверки: требует визуальной проверки

### UX-9. «Уменьшение движения» учитывается только в орбе и каскаде

- Последствия: изображение в выборе области (18) и в превью проверки (18) скруглены сильнее карточек (12–16). Мелкая, но заметная непоследовательность «инженерной» эстетики Linear.
- Решение: фото и панели — `Theme.panelRadius`; миниатюры — `Theme.smallRadius`; рамки строк OCR — добавить `Theme.xsRadius = 4`.
- Сложность: S
- Статус проверки: проверено чтением кода

### UX-24. Направление переходов не соответствует навигации; двойные нижние отступы
- Приоритет: P3
- Файл: `AIHomework/Features/Solve/SolveFlowView.swift:98-120`; `AIHomework/Features/Solve/SolveStages.swift:34, 216`
- Место в коде: `ReviewStage` всегда въезжает справа (`.move(edge: .trailing)`), в том числе по «Изменить» с результата, то есть назад. `ResultStage` въезжает снизу, `Solving` масштабируется, `Selecting` масштабируется 0.97. Плюс `padding(.bottom, 120/130)` поверх `safeAreaInset`.
- Причина: переходы подобраны по отдельности для каждой стадии.
- Последствия: пространственная модель «вперёд/назад» не читается, движение кажется случайным. Это противоречит запросу «стиль motion design, плавно и сдержанно». Внизу результата лишние ~130 pt пустоты.
- Решение: одна ось: вперёд — `.push(from: .trailing)` (iOS 17), назад — `.push(from: .leading)`, направление по сравнению индексов стадий. Ожидание (`recognizing/solving`) — только `.opacity`. Отступы снизу сократить до 16 pt.
- Сложность: S
- Статус проверки: требует визуальной проверки

### UX-25. Карточка «Кнопка действия» открывает настройки сверху, нужный раздел — четвёртый
- Приоритет: P3
- Файл: `AIHomework/Features/Home/HomeView.swift:226-252`; `AIHomework/Features/Settings/SettingsView.swift:46-48`
- Место в коде: `app.isSettingsPresented = true` без якоря; раздел «Кнопка действия» идёт после API и Apple Intelligence.
- Причина: нет передачи целевого раздела.
- Последствия: пользователь видит поля API и не находит инструкцию, которую обещала карточка.
- Решение: `SettingsView(initialSection: .actionButton)` + `ScrollViewReader.scrollTo` в `onAppear`, или отдельный лист с 5 шагами и `ShortcutsLink`.
- Сложность: S
- Статус проверки: проверено чтением кода

### UX-26. Размытие всего стека навигации под непрозрачным сценарием
- Приоритет: P3
- Файл: `AIHomework/App/RootView.swift:24-25`; `AIHomework/Features/Solve/SolveFlowView.swift:19`
- Место в коде: `.blur(radius: 8)` и `.scaleEffect(0.94)` на `NavigationStack`, хотя `SolveFlowView` целиком закрыт непрозрачным `Palette.canvas`.
- Причина: перенесено из «стеклянной» версии, где фон просвечивал.
- Последствия: размытие видно только ~0,4 с перехода, но всё время, пока открыт сценарий (с живой камерой/OCR), GPU пересчитывает размытый слой. Linear вообще не использует размытие.
- Решение: убрать `blur`, оставить `opacity`/`scale` только на время перехода либо скрывать корень (`.opacity(0)` после завершения анимации).
- Сложность: S
- Статус проверки: требует проверки производительности на устройстве

### UX-27. Liquid Glass на iOS 26: системная оболочка станет стеклянной, кастомная — нет
- Приоритет: P3
- Файл: `.github/workflows/ai-homework-ios.yml:44-47` (выбор новейшего Xcode); `AIHomework/Features/Solve/SolveStages.swift:247-266`; `AIHomework/Features/Solve/SolveFlowView.swift:58-91`; `AIHomework/DesignSystem/Buttons.swift:87-105`
- Место в коде: при сборке на SDK iOS 26 `NavigationStack`, тулбары, `searchable`, листы, `Menu`, сегменты и переключатели автоматически получают Liquid Glass. А верхняя панель сценария, нижняя панель действий и кнопки-иконки — плоские Linear-капсулы (`surface2`). `UIDesignRequiresCompatibility` не задан.
- Причина: стиль сознательно заменён на Linear. Системный слой при этом остаётся за ОС.
- Последствия: в «Истории», «Предмете» и «Настройках» навигационные панели стеклянные, а в сценарии решения те же по смыслу элементы плоские — два языка оболочки. Какой Xcode выбирает CI, по коду не видно.
- Решение: стекло — только для плавающих элементов управления над контентом, а не для контента (это совпадает с принципами Apple для Liquid Glass): под `if #available(iOS 26, *)` для нижней панели результата и кнопки «Закрыть» над фото — `.glassEffect(.regular, in: .capsule)` без цветного `tint`, с `GlassEffectContainer`. Карточки, ответ, шаги, поля ввода остаются плоскими Linear. Системные панели не перекрашивать. Альтернатива, если владелец хочет чистый Linear везде, — `UIDesignRequiresCompatibility = YES` (временная мера Apple, не на годы).
- Сложность: S
- Статус проверки: требует визуальной проверки (и проверки версии Xcode в логах CI)

### UX-28. Анимации орба не перенастраиваются при смене состояния
- Приоритет: P3
- Файл: `AIHomework/DesignSystem/AnimatedBackground.swift:53-73`
- Место в коде: `breathing = true` с `repeatForever` выставляется один раз. При смене `isActive` повторный `withAnimation(...){ breathing = true }` ничего не меняет, поэтому темп дыхания (1,0 с ↔ 3,2 с) не переключается. Остановка вращения через `rotation = 0` с `easeOut` поверх `repeatForever` в SwiftUI ненадёжна. При «Уменьшении движения» активный орб — статичная дуга без признака работы.
- Причина: императивный запуск анимаций в `onAppear/onChange`.
- Последствия: орб в заголовке на стадии «Результат» может продолжать крутиться или «дышать» в рабочем темпе. Требует проверки.
- Решение: `TimelineView(.animation(paused: !isActive || reduceMotion))` с углом от времени, или `.phaseAnimator`/`.keyframeAnimator` (iOS 17) с `trigger: isActive`. При `reduceMotion` и `isActive` — пульс прозрачности дуги 0.5↔1.
- Сложность: S
- Статус проверки: требует визуальной проверки

## Чего не хватает до уровня коммерческого AI-продукта

1. **Follow-up в контексте задачи.** У ChatGPT/Gemini/Galaxy AI под ответом есть поле «Спросить ещё» и подсказки («Почему шаг 3?», «Объясни проще», «Похожая задача»). Здесь после ответа только «Изменить/Заново». Минимум — 3 чипа быстрых уточнений под карточкой ответа и поле ввода в `safeAreaInset`, отправляющее в тот же API историю диалога.
2. **Отрисовка формул** (см. UX-20): дроби, корни, степени, системы в двумерной записи, как у Photomath и ChatGPT.
3. **Потоковый вывод ответа.** Сейчас ожидание до 75 с заканчивается разом. Стриминг (SSE в формате OpenAI/Anthropic) с появлением шагов по мере генерации резко снижает воспринимаемое время. В Apple Intelligence — `streamResponse`.
4. **Проверка распознанного «на месте».** Подсветка спорных символов прямо на фото (×/x, 0/O, 1/l), исправление касанием по слову, переключатель «это переменная x» (см. UX-1). Galaxy AI и Circle to Search дают выбрать фрагмент текста, а не только прямоугольник.
5. **Режим «объясни, а не решай»** / уровень подробности (кратко ↔ подробно ↔ для учителя) и «Подсказка без ответа» для самопроверки — стандарт у образовательных AI (Socratic, Gemini).
6. **Копирование и экспорт на уровне шагов.** Долгое нажатие на шаг/формулу → «Копировать», «Копировать как LaTeX», копирование всего решения одной кнопкой (сейчас — только ответ и `ShareLink`).
7. **Явный индикатор отправки данных.** В строке этапов при `routing/model` показывать «Фрагмент изображения отправлен на <host>» с иконкой `arrow.up.forward`. Это честнее и закрывает вопрос владельца о фото на внешних серверах на уровне UX (решение по политике остаётся за владельцем).
8. **Повтор другой моделью / сравнение.** «Решить ещё раз другой моделью» и пометка расхождения с точным решателем, если оба ответили.
9. **Виджет и Live Activity / Dynamic Island** для долгого решения: пользователь уходит из приложения, а результат приходит уведомлением (у Apple Intelligence и ChatGPT это уже есть).
10. **Онбординг первого запуска.** Нет экрана «что умеет / подключите API / настройте кнопку действия»: без API большая часть предметов отвечает «Ответа нет», и пользователь узнаёт об этом только после первой попытки.

Обязательные UI-тесты (XCUITest):
1. «Ввести» → текст `x^2-5x+6=0` → «Решить» → ответ содержит `2` и `3`; кнопка «Копировать» кладёт ответ в буфер.
2. Изображение из буфера → «Решить всё изображение» → проходит через стадии → результат. Проверить, что VoiceOver-объявления стадий отправляются (`XCUIElement` с `accessibilityLabel` стадии).
3. Отмена во время решения возвращает к проверке с сохранённым текстом (после UX-3).
4. Ошибка сети (заглушка URLProtocol) → карточка «Нет связи» с «Повторить», без «Настроить нейросеть» (после UX-4).
5. История: свайп «Удалить», «Очистить историю» с подтверждением, пустое состояние с CTA.
6. Аудит доступности: `XCUIApplication().performAccessibilityAudit()` (Xcode 15+) на главном, результате, истории и настройках — ловит контраст, размеры касания, отсутствие меток и обрезку текста при Dynamic Type.
